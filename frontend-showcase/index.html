Help & Documentation

What This Dashboard Shows

This dashboard simulates an Intelligent Microgrid Energy Management System (EMS). It compares a conventional Rule-Based controller and a Fuzzy Logic controller under the same load, solar, and battery conditions.

Controllers Explained

  • Rule-Based EMS: Hard IF-THEN rules dispatch battery power from deficit and SOC thresholds. It is deterministic and easy to audit.
  • Fuzzy Logic EMS: Uses membership functions (low, medium, high) for deficit and SOC, then defuzzifies a smooth battery setpoint. It is softer and less abrupt than hard thresholds.
  • Baseline: Reference case without intelligent dispatch improvement, used to calculate savings and efficiency.

Input Parameters

  • Load 1, Load 2, Load 3 (kW): Independent demand components. Total load is their combined profile.
  • Solar Scale (0 to 2): Multiplier for solar generation profile. 0 means no solar, 1 means nominal profile, >1 means stronger generation.
  • Battery Capacity (Wh): Stored energy available for charge/discharge over time.
  • Battery Max Power (W): Power ceiling for charge/discharge action. This is applied internally by the selected case.
  • SOC (State of Charge): Battery energy ratio from 0 to 1. Dashboard typically uses 20% to 90% safe band.
  • Time Scenario buttons: Quick presets that set Solar Scale for morning/afternoon/evening/night.

Quick Tuning Guide:

  • Increase Load 1/2/3: Higher demand, usually higher grid import and higher cycle cost.
  • Decrease Load 1/2/3: Lower demand, easier for solar and battery to meet load.
  • Increase Solar Scale: More PV contribution, usually lower grid import and better savings.
  • Decrease Solar Scale: Less PV support, grid and battery must supply more.
  • Increase Battery Capacity: More stored energy buffer; improves ability to shift energy across time.
  • Decrease Battery Capacity: Battery saturates/depletes faster; less support during deficit periods.
  • Higher SOC start: More immediate discharge headroom for deficit handling.
  • Lower SOC start: Controller preserves battery first; grid usage can increase initially.

How to Use

  1. Select a preset case or keep Synthetic Scenario for manual inputs.
  2. Set time scenario and parameters, then run simulation.
  3. Compare Rule-Based vs Fuzzy cards and the grid/SOC charts.
  4. Use animation controls to inspect transient behavior.

Metrics and Charts

Solar Generation: Average solar output over the simulation window.
Battery SOC: Peak battery state-of-charge reached by the controller.
Grid Power: Import/export demand from utility after solar and battery contribution.
Grid Improvement (%): Relative reduction in average grid dependence vs baseline.

Cost Panel Meaning

  • Baseline Cost: Cost of baseline grid profile for one simulation cycle.
  • Optimization Savings: Baseline cost minus optimized cost (currently displayed for fuzzy result).
  • Optimization Efficiency (%): Savings as percent of baseline cost.
  • Why cost can look very small: One cycle is only a short simulation window, so absolute Rs can be tiny. Dashboard now shows higher precision for very small values.

Preset Cases

  • Residential: Typical household load profile.
  • Industrial: Higher and steadier demand profile.
  • High Solar: Strong PV profile, usually lower grid dependence.
  • Low Solar: Weak PV profile, usually higher grid dependence.
  • Small Battery: Lower battery capacity and dispatch limit.
  • Large Battery: Higher battery capacity and dispatch limit.

Active Case Configuration

Below the case selector you can now see the active case summary: selected case, battery capacity, battery max power, and initial SOC. This confirms exactly what the simulator is using.

Notes for Manual Mode

  • Manual controls are active only in Synthetic Scenario mode.
  • Default Solar Scale is set to 0.5.
  • For consistent comparisons, keep one parameter fixed while varying one other parameter at a time.
